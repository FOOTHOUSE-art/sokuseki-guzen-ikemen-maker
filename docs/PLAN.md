## 1. ソースを読んで分かった、計画の修正点

### 1-1. **`pools` を抜き出しても人物像は作れない**(最重要)

| | 実測 |
|---|---:|
| `pools` のキー / 語彙 | 105 / 1,368 |
| **スクリプト全体の日本語文字列リテラル(重複除く)** | **7,094** |
| トップレベルの関数 | 430 |
| トップレベルのデータテーブル(大文字const) | 192 |

**`pools` は語彙の約19%。** 残りは `FVOCAB` `BRAND_DB` `OCCUPATIONS` `INNER_*`(40超)
`SPORT_*` `FOOT_*` `SOLE_*` にある。しかも人物の**筋の通りかた**は語彙ではなく関数側にある。
`generateCharacter()` は約400行で、`vibeProfile` `eraProfile` `chooseRoleByMbti`
`avgHeight` `generateCoordinatedOutfit` を次々に呼ぶ。職業×年齢×MBTI×年代×国籍×体格×服装の
連動はここにしかない。

> **層2は「語彙の移植」ではなく「人物エンジンの切り出し」。**
> 決定Dで足裏・下着・インフォパネルまで要るようになったので、**切り出す範囲はさらに広い**。

### 1-2. 偶然メーカーにシードが無い

`Math.random()` を**190か所**で直接呼ぶ。人物IDも `Math.random()+Date.now()`。
「同じシードから顔と人物像を決める」がそのままでは成立しない。層2の最初の仕事は
抽選ではなく**乱数の一本化**。

同一スコープの関数宣言なので**後勝ち**で、先に書かれたほうは黙って死ぬ。
`buildFullProfileText` だけの話ではなかった。**7件は内面プロフィールの生成器**で、
そのまま層2の切り出し対象に入っている。

| `generateInnerProfile` | 5905 | **6298** |

### 1-4. 偶然は**すでに2段のプロンプト構造**を持っている(v1から判断を訂正)

読み直すと、偶然は次の形で完成している。

## 3. 出力は3段のパイプラインになる(Dの帰結)

決定Dで、いちばん大事な構造が決まった。

```
[1] 即席が顔を合成          1024×1024 / 正面バストアップ / 無地背景
        ↓ 顔の参照画像として添付
[2] 基準リファレンスカード   偶然の buildPrompt(baseMode) 、【顔】だけ即席の記述に差し替え
```

**このメーカーが作るのは [1] と [2] のプロンプト。[3] は既存の経路がそのまま乗る。**
「顔の参照画像が作れるメーカー」という目的が、ここで具体的な形になる。

| | 中身 | 出所 |
|---|---|---|
| (a) 顔参照画像 | 1024×1024 PNG。襟元の服は即席の素材(B) | 即席・現行のまま |

| (d) 派生プロンプト | 既存のまま | 偶然 |

## 4. (c) 基準カードのプロンプト — 仕様

### 4-1. 差し替えるのは【顔】だけ

いまの【顔】は `c.faceLine` `c.tearBags` `c.nose` `c.hairStyle` … と偶然の語彙を読む。
これを即席の状態 `s` と微調整 `adj` から作る `faceToJa(s, adj)` に差し替える。

- **素材ID → 語彙は一対一**。`JA_LABEL` の拡張で足りる(v0.9157 で実装ずみ)
- **微調整の言語化にはしきい値表が要る。** 25スライダーそれぞれに
  「無視する / やや / はっきり」の境界を決める。**ここが (c) の実質的な仕事量**
- **`none` の軸は行を出さない。**「眼鏡なし」「ひげなし」とは書かない(下記の原則7)

### 4-2. 顔参照画像を添付するための前置きを**新しく書く**

偶然の `refPrefix()` は「添付=基準カード」を前提にしていて、そのままでは使えない。
[1]→[2] 用の前置きが要る。**ここを外すと事故が出る。**

添付するのは**バストアップ・シャツ姿・正面のみ**の画像。作らせたいのは
**全身・下着・複数ビュー**のカード。つまり画像と指示が意図的に食い違う。

書くべきことは4つ。

1. 添付画像から学ぶのは**顔立ち・髪・肌の色と質だけ**
2. **服装・構図・画角・パネル構成は本文の指示に従う**(画像の襟元は無視してよい)
3. **顔の側面パネルは、添付の正面から自然に推定して描く**
4. **髪型と髪色は本文にも明記する。**実写化の検証で、面積の大きい要素(髪)ほど
   書き換えられると分かっている。画像とテキストの二重で押さえる

### 4-3. 非性的の担保は**削らずに引き継ぐ**

基準カードには下着パネルと足裏の拡大パネルがある。偶然のプロンプトには
「衣料品の商品写真と同じ即物的なトーン」「性的な演出・強調・ポーズは一切しない」
「未成年に見える描写を避ける」といった指定と禁止事項ブロックが入っている。
**移植のときに縮めない。** 短くすると生成側の出力が崩れる。

### 4-4. OpenAI のベストプラクティスの当て方(C)

| 原則 | この生成器での実装 |
|---|---|
| 指示を先頭に置き `###` や `"""` で指示と入力を分ける | 出力指示 → 人物データ(`"""`) → 遵守事項 の3ブロック固定 |
| 文脈・結果・長さ・形式・スタイルを具体的に | パネル構成・比率・情報欄の項目を毎回明示(偶然の既存文がすでにこの形) |
| 出力形式を例で示す | 参照画像の添付がこれに当たる |
| **曖昧な形容を減らす** | 微調整→語のしきい値表で機械的に決める。書き手の感覚を入れない |
| **「しない」でなく「する」を書く** | `none` の軸は行ごと出さない。ただし §4-3 の禁止事項ブロックは例外(必要な明示) |
| ゼロショットから始める | 少数例は入れない。記述の精度で勝負する |

### 手順1の具体案

偶然のスクリプトは1つの巨大なIIFE。`Math` の差し替えは `const` 再宣言になるため使えない。

1. 先頭に `let RNG = Math.random; const rand = () => RNG();`
2. `Math.random()` → `rand()` を機械置換(190か所)
3. `RNG = mulberry32(seed)` で差し替える

**置換後に `Math.random` の残存を数えて0を確認する。**
即席で踏んだ「文字列の置換は空振りしても通る」(知見5-7)と同じ形の地雷。

### 手順2の切り出し方

`generateCharacter` は `getFixed()` `getInitial()` と DOM を読む。**引数に外出しするのが先。**
関数を「次の `function` まで」のような**文字列の位置で切り出さない**
(知見5-8。即席では `colorizeCloth` ほか4つを巻き込んで消した)。

**二重定義の8件は、行番号で指定して生きているほうを運ぶ**(§1-3の表)。
名前で検索して最初に当たったものを取ると、7件は死んだ版を掴む。

**Gにより落とせるもの。** `generateCharacter` の引数 `groupCtx` と大域の `FRIEND_CTX`

## 7. 引き継ぐ地雷
