## 1. 手で拾わずに機械で切り出した

`extract_person.py` が `index.html` から `generateCharacter` の**依存閉包**を取る。

| | |
|---|---:|
| トップレベルの宣言 | 673 |
| **依存閉包として残ったもの** | **415**(入口は `generateCharacter` と `buildPrompt`) |
| 決定Gで落としたもの | 20 |
| DOMを読んでいたもの | 5 |

**手で拾ってはいけない理由が3つ、実際に出た。**

1. **二重定義8件。** 名前で検索すると7件は死んだ版を掴む。深さで数えて後勝ちを採る
2. **字下げが揃っていない。** `chooseFashionProfile` は4字下げのままトップレベルに置かれている。
   字下げで判定すると落ちる。**波かっこの深さで判定した**
3. **正規表現リテラルを文字列と誤認すると範囲が壊れる。** `.replace(/"/g, ...)` の `/"/` を
   文字列の開始と読むと、そこから先の宣言を全部飲み込む(最初の実装で実際に起きた)

## 2. 手順1 — 乱数の一本化

`Math.random()` を **158か所**(閉包内)`rand()` に置換した。文字列の中の
`Math.random` を巻き込まないよう、文字列を潰した版で位置を数えてから本文を書き換える。

**種を撒く前に呼ぶと例外を投げるようにした。**

```js
let RNG = () => { throw new Error('setSeed() を先に呼ぶこと。種なしの生成は再現できない'); };
```

`Math.random` にフォールバックさせると、撒き忘れが静かに通って再現できない人物が混ざる。

### 置換だけでは足りなかったもの

**計測値は事前にシャッフルした山札から順に引く方式だった。**
山札もカーソルも呼び出しをまたいで残るので、同じ種でも2回目が変わる。
`setSeed()` のたびに山札を作り直すようにした。

**人物IDが `Math.random() + Date.now()` だった。**
種から決まるように変えた。同じURLで同じIDに戻る。

残る非決定は `createdAt`(生成時刻)だけ。人物の内容ではないので検査から外した。

  OK  髪を変えると層2の髪も変わる
  OK  顔を渡さないと例外になる
  OK  しきい値内(chinY 3)は書かれない
  OK  はっきり(eyeGap -14)が語になる

出力の例(seed 2024):

> 丸型の輪郭。二重の奥まった目。上がり眉。高く長い鼻筋。小さな口。
> そばかすとニキビ跡と毛穴の質感。髪は栗色の短めのサイドパート。肌は小麦色。無精ひげ。

### しきい値の表

微調整25軸すべてに `[無視する上限, はっきりの下限]` を置いた。
**あいだが「やや」。表の外では語を決めない。**

| 種類 | 軸 | 無視 | やや | はっきり |
|---|---|---|---|---|
| px(標準) | eyeGap / browY / browGap | ≤3 | 4〜8 | ≥9 |
| px(小さめ) | lidDrop / outerY / chinY / noseY / mouthY ほか | ≤3 | 4〜7 | ≥8 |
| px(細かい) | browTilt | ≤1 | 2〜4 | ≥5 |
| px(口角) | mouthCorner | ≤2 | 3〜6 | ≥7 |
| 倍率(輪郭) | faceW / faceH | ±0.03 | 0.03〜0.07 | ≥0.08 |
| 倍率(目) | eyeScale / eyeWidth / eyeHeight | ±0.03 | 0.03〜0.08 | ≥0.09 |
| 倍率(鼻口) | noseW / lipThick / lipWidth | ±0.04 | 0.04〜0.09 | ≥0.10 |
| 倍率(眉の濃さ) | browAlpha | ±0.05 | 0.05〜0.19 | ≥0.20 |

`lidRise` は正の向きだけ語にする。下まぶたが下がる指定は顔として意味を持たない。

**`none` の軸は行ごと書かない。**「眼鏡なし」「ひげなし」とは出力しない(OpenAIの原則7)。

## 6. 手順2b — 層2から顔立ちを外した

**消すのではなく、即席の値を注入する形にした。**
偶然側は `facePreset` や `hairStyle` を服装・雰囲気・レア判定の重みに使う。
消すと人物の筋が通らなくなる。

```js
const f = faceToJa(rollState, adj, presets);
setConfig({ face: f.inject, strictFace: true });
setSeed(seed);
const c = generateCharacter('full');
```

`strictFace: true` にすると、**顔が渡されないまま生成しようとしたら例外**になる。
層2が黙って自分で顔を決めるのを防ぐ。渡す値は25キー。

### 顔立ちプリセットは画像から逆算する

抽選で顔を作ったときも、偶然側にはプリセット名が要る。
層2に選ばせると「層2が顔を決める」ことになるので、**素材から最も近い35種を逆算した**。
目・輪郭・鼻・口を重く見る重みづけで、**35種すべてが自分自身に戻る**。

### 途中で見つかったもの

**`chooseFaceAgeCompatible()` が年齢で顔立ちを上書きしていた。**
55歳以上なら「やりらふぃー系」を外す、といった調整。顔が画像で決まる以上、
ここは通してはいけないので、`CFG.face.facePreset` があるときは素通しにした。

**これで年齢が顔を縛らなくなった。** 若く見える顔で60歳の人物が出ることがある。
§8 の判断に挙げた。

## 8. 決定H — 雰囲気を保ったまま、その年齢の顔にする

顔は画像が正、年齢は層2が持つ。両方を立てるために、**顔立ちは変えず年齢だけ足す**。
`ageFaceNote(age)` が差分を返す。

| 年齢 | 足すもの |
|---|---|
| 〜21 | 肌の張り、頬のわずかな丸み。しわを作らない |
| **22〜29** | **なし(画像のまま)** |
| 30〜39 | 目尻の薄い笑いじわ。フェイスラインは保つ |
| 40〜49 | ほうれい線、上まぶたのかぶさり、こめかみの白髪 |
| 50〜59 | 額のしわ、目の下のたるみ、フェイスラインの緩み、全体の白髪 |
| 60〜 | 深いしわ、首のしわ、眉と髪のはっきりした白髪 |

**素材の年齢は1つしかない。** 素体を20代半ばとみなし、22〜29歳なら何も書かない。
書かなければ画像のまま出る。

**髪型と髪色は年齢で変えない。** 髪は実写化で最も書き換えられやすい部位で、
ここを動かすと画像から離れる。45歳以上の白髪だけ、混ぜる量として足す。

**この差分は【顔】の記述に混ぜず、別の行として返す。**
混ぜると、画像から来た顔立ちと、年齢で足した分の区別が付かなくなる。

## 9. 手順6c — 顔参照画像の前置き

`refPrefixFace({ age })` が返す。偶然の `refPrefix()` は「添付=基準カード」前提で使えない。

```
【参照画像あり・重要】添付した画像は、この人物の顔だけの参照。
顔立ち・髪型・髪色・肌の色と質は、この画像に従う。
【年齢】画像の顔の雰囲気と造作を保ったまま、58歳の顔として描く。
同じ人物が年を重ねた姿とし、別人にしない。目尻と額に浅いしわ、ほうれい線を
はっきり入れる。上まぶたのかぶさりと目の下のたるみを加え、フェイスラインを
やや緩める。白髪を全体に少し混ぜる。
【画像から読み取らないもの】服装・構図・画角・背景・パネル構成は本文の指示に従う。
画像の襟元は顔を見せるための仮のもので、着ている服の指定ではない。
【側面】顔の側面は、画像の正面から自然に推定して描く。
【描き直す】画像を切り貼りせず、本文の光と画角に合わせて一から描き直す。
肌の質感・光の向き・影・色味を全体でそろえ、1枚として自然に撮影された画像に仕上げる。
```

文体は偶然のプロンプトに合わせて「〜する」で統一した。
です・ます と混ぜると指示の粒がそろわない。

## 12. 手順7 — レア判定の統合

即席は**確率の掛け算**、偶然は**点の足し算**で持っている。**点にそろえた。**

```
pt = clamp(round(6 * log10(1/p)), 2, 30)     p=0.033(三白眼)→9pt / p=0.25(ほくろ)→4pt
```

イケメン度は**即席の実測をそのまま使う**。偶然の語彙加点は使わない。
移植が正しいことは分布で確かめた。**引き継ぎ資料の記載と一致する。**

| | 資料 | 移植後(4,000回) |
|---|---|---|
| 幅 | 51〜93 | 52〜92 |
| 中央 | 77 | **77** |

### 落とした8規則

300シードで発火率を測って決めた。**理由を残さないと、あとで戻される。**

| 規則 | 理由 |
|---|---|
| **左右対称に近い顔** | **実測100%。** 素材が左右反転なので必ず成立する。全員に +8pt が乗るだけ |
| 明色髪 / 泣きぼくろ / レアな肌の特徴 | 即席の「明るい髪色」「ほくろ」「そばかす」と二重になる |
| 長いまつ毛 | 即席に差が無いので「標準」で固定。当たらない |
| 彫りの深い顔立ち / 整った歯列 / えくぼ | 層2が値を持たない軸を見ている |

**当たらない規則も落とす。** 残しておくと、あとで誰かが値を足したとき静かに効きだす。

段の分布(400回): RARE 42% / NORMAL 40% / SUPER RARE 13% / LEGEND 6%。

### 途中で見つかったもの — 人種が素材と食い違っていた

偶然の既定は国籍も人種も「ランダム」。27か国から一様に引くので、
**実測で97%が外国籍、大半が非アジア系**になる。
即席の素材は日本人の顔で作られている(顔立ちプリセットに しょうゆ顔・縄文/弥生 がある)。
**画像が日本人の顔で、文章が「フランス、白人系」になっていた。**

**決定I で、国籍・舞台・人種のすべてを日本に固定した。**
これで街並み・看板・行き交う人まで日本になる。

**段を引き直す必要があった。** 「外国籍 +8pt」が当たらなくなり、
「左右対称 +8pt」も落としたぶん、全体が下へ寄って NORMAL が81%になった。

NORMAL 49% / RARE 40% / SUPER RARE 10% / LEGEND 2% に戻した。

## 15. 6d の結果 — 顔がイラスト調になった原因

**手順6bで【顔】をまるごと差し替えたとき、`realismSpec()` を一緒に消していた。**

偶然の【顔】には、顔の語彙のほかに**語彙に依存しない指示**が混ざっていた。

| 消していたもの | 中身 |
|---|---|
| **`realismSpec`** | **「実在の人物の写真のような生物学的リアリズム。毛穴・小さな凹凸・自然な色ムラ。陶器のように均一に滑らかにしない。AI美形を避ける」** |
| `teethLine` | 歯並びと色。**基準カードに歯のパネルがある(決定D)のに落ちていた** |
| `hairDetailLine` | 前髪・毛量・整髪 |
| `faceExtraLine` / `originFaceLine` | 顔の補足・出自の面影 |

差し替える範囲を「語彙の部分だけ」に狭めて、この4つを戻した。

### 加えたこと

**否定形で「イラストにしない」と書くより、写真の作りを具体的に書くほうが効く**
(OpenAIの原則7)。**造作(何が写っているか)と画風(どう描かれているか)を分けて指示する。**

```
【画風】参照画像は素材を合成した絵。ここから読み取るのは造作だけにする。
目・鼻・口・眉・輪郭の位置と形と比率、髪の生え方と流れ、肌の明るさ。
線の引き方・塗り・陰影の付け方は写真に置き換える。
【実写の作り】85mm相当のレンズで撮った日本人男性の写真として描く。
肌は毛穴と産毛が見え、額と鼻筋にわずかな皮脂の照りがある。眉と睫毛は一本ずつ生えている。
唇には縦の細かいしわ。虹彩には放射状の繊維と外周の暗いリングがあり、
角膜のハイライトは光源ひとつぶん。髪は毛束を線で囲まず、生え際は地肌が透けて
一本ずつ植わって見える。肌の色は面で塗り分けず、連続した階調でつなぐ。
骨格の陰影(眼窩・頬骨・下顎角)を、光の回り込みとして自然に出す。
```

画質の指定も `雑誌グラビアではなく設定資料風` → **`AI感を抑えた自然写真`** に変えた。
資料であることはパネル構成が担っているので、質感は写真に寄せてよい。

**検査に7項目足した。** 実写化の指示が消えたら落ちる。

### 2回目の結果

実写になった。髪型・三白眼・剣眉・逆三角の輪郭はすべて保たれ、側面も同一人物に見える。
**襟元の漏れもない**(服「なし」の効果)。

残った差は3つ。いずれも判断待ち(計画 §8 j〜l)。

| | 起きたこと | どうするか |
|---|---|---|
| j | 指示にない「顔：斜め(45度)」パネルが増えた | **足した。**正面と側面の間を埋める |
| k | 歯のパネルが「イー」ではなく自然な笑顔になった | **直した。**下記 |
| — | 「ニキビ跡」がそばかす状の点として描かれた | **直した。**下記 |

### k — 指示どうしが喧嘩していた

歯のパネルが笑顔で返ったのは、指示が足りなかったからではない。**2つの指示が反対を向いていた。**

| 場所 | 中身 |
|---|---|
| 出力形式 | 「イー」と口を横に広げて上下の歯列を見せる、歯科の資料撮影風 |
| **`teethLine`(復活させたもの)** | **歯は笑ったときに自然に見える範囲でのみ描写し、常に歯を見せた表情にはしない** |

出力形式の側に「（このパネル以外では〜）」という但し書きが既にあるので、
**`teethLine` の末尾を落として一本化した。** そのうえでパネルの指示を強めた。

```
…歯科の資料撮影風の即物的な表情にする。笑顔にしない。口角は上げず、
唇を左右いっぱいまで水平に引いて、上下の歯列全体と歯ぐきの際まで見えるようにする
```

**復活させた行が、別の指示と喧嘩することがある。** 戻すときは前後を読む。
検査に「歯の但し書きが1か所だけ」を足した。

### 年齢は向きを書かない

`同じ人物の若いころの姿` / `年を重ねた姿` と書き分けていたが、**向きを書くと
参照画像に年齢があるかのように読める。** 素材の年齢は1つで、上にも下にもずらす。
`同じ人物の姿とし、別人にしない。` に統一した。

### 肌ディテールは「どこに何があるか」まで書く

`ニキビ跡` とだけ書いたら、色の点として描かれた。跡は点ではなく浅い凹凸。

```
変更前: そばかすとニキビ跡と毛穴の質感。
変更後: 頬に薄いニキビ跡の凹凸(色の点ではなく、浅いくぼみとして描く)。小鼻のまわりにわずかな赤み。
```

**語彙を並べるだけでは足りない。** 位置と、何でないかまで書く。

## 17. 写しを作らずに両方で動かす

node で検査するために即席の抽選とイケメン度が要るが、`app.js` は
engine / warp / loader を読むのでブラウザでしか動かない。
最初は手で写したが、**それは引き継ぎ資料 §5-6 で踏んだ地雷そのもの**
(UIとエンジンで同じ処理を二重に持ち、片方だけ直して「直った」と誤認した)。

**生成物にした。**

```
app.js ──(extract_sokuseki.py)──▶ sokuseki.js     node 用
app.js ◀──(1行の再輸出)────────── sokuseki.browser.js  ブラウザ用
```

`base_card.mjs` と `rarity.js` は `./sokuseki.js` を読むだけ。
**組み込みのときはファイルを置き換える。** 呼ぶ側は何も変えない。

### 切り出しで踏んだこと

依存を識別子の名前で辿るので、**関数の中のローカル変数が、同じ名前の
トップレベル宣言を連れてくる。** `geometry` の中の `const C = chin - noseBase;`
(人中の長さ)が、`const C = new E.Compositor();`(合成器)を連れてきて node で落ちた。
名前で外し、engine を呼ぶものが残っていないか毎回数えるようにした。

`base_card.mjs` から `fs` も外した。顔立ちプリセットの読み込みは呼ぶ側にまかせる
(node は fs、ブラウザは fetch)。**ここで片方に決めると、もう片方で動かない。**
