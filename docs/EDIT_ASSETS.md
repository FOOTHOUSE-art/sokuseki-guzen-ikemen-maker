# 素材を手で直すとき

顔の輪郭・髪型・目・鼻・口といった**素材そのもの**(WebP画像)を描き直したり、
新しく足したりするときの手順。**直してよい。** ただし守るものがいくつかある。

素材は即席メーカー側(`assets/`)にある。このリポジトリには入っていない。

---

## 1. 全素材で共通の座標

**1024×1024 の同じ位置に描く。** ここがずれると、合成したとき全部ずれる。

| | |
|---|---|
| 虹彩の中心 | (512, 486) |
| 半瞳孔 | 95px |
| 頭頂 | y = 154 |
| あご | y = 769 |
| 鼻孔 | y = 614 |
| 唇の合わせ目 | y = 667 |
| 首の上端 | y = 524 |
| 肌の基準色 | (240, 205, 178) |
| 乗算の中立値 | **232** |

作業は1024×1024の全面でやり、**最後に bbox で切り抜いて `crop.json` に
`[x, y, w, h]` を書く。** 切り抜きを更新し忘れると位置がずれる。

## 2. レイヤーの種類で描き方が変わる

| 種類 | 素材 | 描き方 |
|---|---|---|
| **over** | 顔・耳・髪・眉・目core・服・眼鏡 | 普通に描いてよい |
| **乗算** | 目shade・鼻・口・涙袋・肌ディテール・ひげ | **232が中立。** それより暗ければ暗くなり、明るければ**ベースを明るくする** |

乗算レイヤーには `rgb > 232` の画素が 384,950px ある(鼻梁のハイライト・涙袋・
まぶたのツヤ)。**ここを潰すと立体感が消える。**

**明るくできる上限は 255/232 = 1.099倍。** 白い艶はこれでは出ないので、
`over` で重ねる別の層になっている。乗算レイヤーに白い艶を描いても出ない。

## 3. 直したら `metrics.json` を測り直す

イケメン度と変形の基準になっている。**測り直さないと、見た目と数字がずれる。**

| 素材 | 測るもの |
|---|---|
| 輪郭 | chin / wEye / **wEyeNoEar** / wCheek / wJaw / taper |
| 目 | w / gap / top / cy、虹彩の cx / cy / rx / ry |
| 眉 | bottom / inner / outer |
| 鼻 | **wing2**(小鼻の輪郭線幅) / base |
| 口 | top / bottom / cy / w |
| 髪 | hairline |
| 服 | lo / hi(着色のための輝度域) |

**`wEyeNoEar` は耳を除いた顔幅。** 顔素材には耳が描かれているので、
そのまま測ると輪郭を変えても値が動かない(実際にこれで評価が中央値33になっていた)。

**`wing2` は小鼻の輪郭線で測る。** 陰影まで含めると、わし鼻214px・上向き鼻244pxに
なって評価が14まで落ちる。正しく測ると80〜99px。

## 4. 上書きしたとき何が起きるか

**エラーは出ない。** `loader.js` は `crop.json` の `[x0, y0, w, h]` を見て、
画像を左上に置いてから `w × h` だけを読む。

```js
const [x0, y0, w, h] = crop[rel];
ctx.drawImage(bmp, 0, 0);
const src = ctx.getImageData(0, 0, w, h).data;
```

| したこと | 何が起きるか |
|---|---|
| **サイズを変えずに上書き** | **問題なし** |
| サイズが大きくなった | **黙って右と下が切り落とされる**。`w × h` しか読まないため |
| サイズが小さくなった | **黙ってずれる**。左上に寄って読まれるので、余白の付き方が変わった分だけ動く |
| ファイル名を変えた | **止まる。** `crop.json` にキーが無いと `null` が返り、合成が落ちる |

**残骸を消すだけならサイズは変わらないので、上書きで完結する。**
気をつけるのは抜けを足すときだけ。

## 5. Photoshop で直して上書きする

**それでよい。** 素材はただの WebP で、特別な形式ではない。守るのは4つ。

### 4-1. 画像のサイズを変えない

素材は bbox で切り抜いてあり、`crop.json` の `[x, y, w, h]` で元の位置に戻している。
**幅か高さが変わると、その分だけ画面上でずれる。**

- **残骸を消すだけ** → 内側が減るだけなのでサイズは変わらない。**そのまま上書きでよい**
- **抜けを足す** → **切り抜きの外にはみ出す。ここが落とし穴**

はみ出すときは、Photoshop で

1. カンバスサイズを 1024×1024 に広げる(`crop.json` の x, y ぶん左上に余白を足す)
2. 直す
3. 透明部分を切り詰めて保存(イメージ → トリミング → 透明ピクセル)
4. **`crop.json` の `[x, y, w, h]` を測り直して書き換える**

4を忘れるとずれる。`tools/mask_editor.html` に読み込ませると、新しい値を出せる。

### 4-2. sRGB で、プロファイルは埋め込まない

肌の基準色 (240, 205, 178) と乗算の中立値 232 は**数値そのものが基準**。
カラープロファイルが埋まっていると、ブラウザが色変換して数値がずれる。
「Web用に保存」または「プロファイルを埋め込まない」で書き出す。

### 4-3. ロスレスで保存する

素材は WebP q90(非可逆)。**開いて保存を繰り返すと劣化が積もる。**
Photoshop の WebP 書き出しで**ロスレス**を選べば、そこから先は劣化しない。
ファイルサイズは増えるが、素材485点で6.27MBなので数点なら誤差。

### 4-4. 直したら測り直す

| 直したもの | 測り直すもの |
|---|---|
| 髪 | `metrics.json` の `hairline` |
| 輪郭 | `chin` / `wEye` / **`wEyeNoEar`** / `wCheek` / `wJaw` / `taper` |
| 鼻 | **`wing2`**(小鼻の輪郭線幅) / `base` |
| 目・眉・口 | 対応する実測 |
| サイズが変わった | `crop.json` の `[x, y, w, h]` |

`hairline` と `crop` は `tools/mask_editor.html` が出せる。それ以外は python 側の実測が正。

### 4-5. 確認するとき

`serve.py` を使う。通常の `http.server` だとブラウザが古い画像を掴んだままになる。
それでも変わらなければ Ctrl + Shift + R。**暗い髪色と明るい髪色の両方で見る**(§11)。

## 6. 手直しの道具

`tools/mask_editor.html` をブラウザで開く。サーバも設定も要らない。
**Photoshop で直すなら、こちらは検算に使うとよい**
(離れた塊を数える / `crop` と `hairline` を測る)。

**抽出したものと原画を並べて、マスクを塗り直す道具。**
髪の毛を一から描くのではなく、**原画から戻すか、消すか**の2択にしてある。

| 読み込むもの | |
|---|---|
| 抽出したもの | 必須。これを直す |
| **原画** | **「戻す筆」の元。** これが無いと抜けを埋められない |
| 下敷き | 顔・耳などの合成画像。位置合わせに使う |
| `crop.json` | 切り抜かれた素材を 1024×1024 の元の位置に戻して開く |

| できること | |
|---|---|
| 戻す筆 | 原画から色とアルファを持ってくる。**もみあげの欠けはこれで埋める** |
| 消す筆 | アルファを削る |
| **離れた塊の測定** | 本体から離れた連結成分を、面積と離れ距離つきで並べる |
| まとめて消す | 光っている塊を一括で消す。取り消せる |
| 書き出し | WebP(切り抜き済み) / PNG(1024のまま)、`crop` と `hairline` の値 |

### 離れた塊は「消す前に見る」

幽霊の髪は頭蓋から60px以上離れて出る。既定のしきい値もそこに合わせてある。
**ただし刈り上げも同じ条件に当たる。**「半透明・肌の上・本体から離れている」は
残骸の条件であると同時に、刈り上げの条件でもある。

だから**自動で消さない。** 光らせて、面積と距離を数字で出して、
目で見てから消す作りにした。抽出を88%まで上げても後段が52%に戻していたのは、
この取り違えが原因だった。

### 書き出したあと

`crop` と `hairline` は開いている画像から測り直した値が出る。
**`crop.json` と `metrics.json` を書き換えるのは手作業。**
生え際は中央帯(x 452–572)で α>128 の一番下の行として測っていて、
**元の実測とは ±1 で一致する**(hair01 270/269、hair02 299/300、hair03 341/340)。

`metrics.json` の残り(輪郭の chin や鼻の wing2 など)はこの道具では測れない。
そこは python 側の実測が正。

## 7. 髪は一から描かない

**新しい髪型の抽出は `pipeline_v18.py` で処理する**(即席メーカー側)。
手で切り出すと、次の3つが必ず出る。**手直しは、抽出したあとに上の道具でやる。**

- **幽霊の髪** — 頭蓋から60px以上離れた破片(旧素材の hair12 に 8,736px あった)
- **もみあげの欠け** — 回復率が落ちる(hair28 が67%、hair06 が69%)
- **刈り上げの残骸判定** — 刈り上げは「半透明・肌の上・本体から離れている」という
  残骸の条件に一致してしまう。抽出を88%まで上げても、後段が52%に戻していた

判別に効くのは**局所分散(5×5)**。髪・刈り上げ・ハイライトが 8〜27、
素肌と背景が 0.5〜1.7。色度・輝度・連結性はすべて失敗した。

## 8. 素材の作りで、やってはいけないこと

| | |
|---|---|
| 耳 | **顔素材に描かれている**(耳マスクの99.8%が一致)。輪郭を直すと耳も動く。耳だけ位置を動かすと必ず二重に見える |
| 眼窩 | 中央で繋がっている。左右に割って動かすと切断面が重なる |
| ドレスシャツ | 前立てが描かれていない。ネクタイとセットが前提 |
| 肌ディテール | 口の穴が焼き込まれていた(15,660px)。赤みが届かないリングが白く残る |
| 描画順 | 変えない。とくに **耳 → 髪**。逆にすると耳の上端に暗い欠けが出る |

## 9. 新しい素材を足すとき

差し替えではなく**足す**場合、5か所を直す。

1. `assets/` に WebP(q90、bboxで切り抜き)を置く
2. `assets/crop.json` に `[x, y, w, h]`
3. `assets/metrics.json` に実測
4. `assets/parts.json` の `axes.<軸>.options` に `{id, label, w}`
5. **`engine/face_text.js` の `JA` と `M` に語彙を足す**

5を忘れると、その素材が選ばれたときプロンプトに `undefined` が混ざる。
画面を見ただけでは気づきにくい。**`node engine/test_vocab.mjs` が落ちる。**

`M`(偶然の語彙への対応表)も足す。忘れても落ちないが、
人物像側の服装や雰囲気の重みづけが既定に落ちる。

## 10. 直したら流すもの

```bash
node engine/test_vocab.mjs                                        # 語彙・実測・crop・undefined
python3 tools/verify_presets.py engine/face_presets.json engine/parts.json
node engine/test_face_bridge.mjs                                  # 逆算 35/35
npm test                                                          # 全部
```

`engine/parts.json` `metrics.json` `crop.json` は**アプリのもののコピー**。
素材を直したら、アプリ側を直してから `engine/` にコピーし直す。

## 12. 眼鏡から目と耳を消した(2026-08-20)

`16_glass` の110点すべてに、**レンズの中にまぶたと虹彩がそのまま焼き込まれていた。**
こめかみの外にも、耳や髪の破片が散っていた。

`tools/clean_glass.py` で消した。**残した 1,023,842px / 消した 312,650px。**

### 大きさでも明るさでも分けられない

| 試したこと | なぜ駄目か |
|---|---|
| 明るさで切る | **メタルフレームが消える。** 明るいのはフレームも同じ |
| α で切る | **縁なしのレンズ枠線が消える。** 枠線は薄い |
| 小さい成分を捨てる | **縁なしの枠線は 78px。** まぶたの弧(168〜325px)より小さい |

### 効いた分け方 — **全ファイルに同じ形で写っているものは眼鏡ではない**

フレームは種類ごとに形が違う。まぶたの弧は元が同じ写真なので、
**110点すべてに1px単位で同じ位置に出る。** その共通部分(1,192px)だけを消した。
中央48pxは鼻当てなので除く。

そのうえで、こめかみの外に散った粒を「60px未満の連結成分」として捨てる。

### **薄いというだけで捨ててはいけない**

一度これで失敗した。ハーフリムの下リムを測ると

    α の中央値 55 ／ 輝度の中央値 205

**まぶたの残骸と見分けが付かない。それでもフレームである。**
薄い画素を「フレームの芯から2px以内か」で選り分けたところ、
縁なしのレンズ枠線とハーフリムの下リムが消えた。

残骸は位置(全ファイル共通)で消してあるので、**濃さで二度目の選別をしない。**
いまは浮いた成分が110点すべてで0個になっている。

### やり直すとき

```bash
python3 tools/clean_glass.py <16_glass のフォルダ> assets/crop.json <出力先>
```

**切り抜きが変わるので `crop.json` も書き換わる**(110件)。
出力先に crop_16_glass.json が出るので、`assets/crop.json` に反映する。
`engine/crop.json` は検査用のコピー。こちらも合わせる。

## 13. 残課題の3素材を測った(2026-08-20)

引き継ぎ資料に「hair14 左首に肌の薄片」「hair28 もみあげ67%」「hair06 69%」とある。
**直す前に測ったら、直す必要がなかった。**

| 素材 | 離れた塊の最大 | 塊の数 | 不透明画素 |
|---|---:|---:|---:|
| hair14 | **16px** | 10 | 184,291 |
| hair28 | **6px** | 22 | 130,866 |
| hair06 | **7px** | 10 | 106,872 |

離れた塊は素材全体の 0.01% 以下。目視でも hair14 の毛先はきれいに出ていて、
「左首の肌の薄片」に当たるものは無い。首から下(y≥500)で肌色に近い画素は86pxだが、
x 280–740 に散っているので薄片ではなく、アンチエイリアスのハイライトが
肌色域に入っただけ。

**「もみあげ67%」は旧素材との比であって、見た目の欠けではない。**
§5-3「旧素材を正解とみなさない」がそのまま当てはまる
(旧素材には幽霊の髪が hair12 で 8,736px あった)。

参照画像に写らず、生成AIが読み取る大きさでもない。**触る理由は、
実際に出力で気になったときに作る。**

黒髪だけで確認して3件見逃した(ハイライトの穴 33,553px、輝度レンジのずれ、
耳の輪郭線の残骸)。**明るい髪色でも必ず見る。**

そして**測る対象そのものを疑う。** 「眉目の残骸」として数えていた画素の
89〜100%が刈り上げだったことがある。**良い版が悪く見え、悪い版が良く見えていた。**
